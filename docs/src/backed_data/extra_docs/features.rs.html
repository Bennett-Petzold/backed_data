7/*!
8Features are broken into four category headers. The default features are
9`bincode`, `directory`, and `zstd`. With no features available, synchronous
10[`BackedEntry`][`crate::entry::BackedEntry`] is available with plainfile disks,
11but the library needs at least one `coder` feature or custom coder implementation
12to provide the entry.
13
14`all_disks` enables all disk types, and `all_formats` enables all coder formats.
15
16# Library Functionality
17* `async`
18    * Provide asynchronous variants library-wide, usually methods prepended with `a_`.
19        Enabled by any [executor feature](#async-executors).
20* `array`
21    * Provide [`BackedArray`][`crate::array::BackedArray`] to split one array
22        into multiple smaller [`BackedEntry`][`crate::entry::BackedEntry`] arrays in storage,
23        but represent as a single array to the user.
24* `unsafe_array`
25    * Enable features for `array` that requires `unsafe` code. Needed for mutable iterators
26        and access on containers that return handles instead of direct references (e.g.
27        [`SecretVecWrapper`][`crate::entry::disks::encrypted::SecretVecWrapper`]).
28* `directory`
29    * Provide [`DirectoryBackedArray`][`crate::directory::DirectoryBackedArray`] to wrap
30        [`BackedArray`][`crate::array::BackedArray`]. This simplifies appending data to
31        the backing arrays and saving/reloading arrays.
32
33# Async Executors
34None of these features are necessary to use an async executor, but they provide
35a correct [`AsyncFile`][`crate::entry::disks::AsyncFile`] for the `Plainfile`
36disks to use. They also give convenience handles in
37[`blocking`][`crate::utils::blocking`].
38
39* `tokio`
40* `smol`
41
42# Disk Types
43`Plainfile` variant disks are available with no features. Some
44[executor feature](#async-executors) needs to be chosen in order for those base
45types to have asynchronous file access.
46Custom disks can be defined by implementing
47[`WriteDisk`][`crate::entry::disks::WriteDisk`] and [`ReadDisk`][`crate::entry::disks::ReadDisk`]
48(and/or the async versions).
49They can also be defined using [`crate::entry::disks::custom`] types.
50
51* `all_disks`
52    * Enable all disk types.
53* `encrypted` - [`Encrypted`][`crate::entry::disks::Encrypted`]
54    * Uses [`secrets`](https://github.com/stouset/secrets) and
55        [`aes-gcm`](https://docs.rs/aes-gcm/latest/aes_gcm/) to encrypt all
56        data stored to disk, and minimize the risk of memory-peeking in the
57        encryption/decryption process.
58* `mmap` - [`Mmap`][`crate::entry::disks::Mmap`]
59    * Enables the use of [`mmap`](https://en.wikipedia.org/wiki/Mmap) calls on
60        UNIX systems (guarded by `mmap_impl`) to replace regular file I/O.
61        Reuses mapped memory when possible to reduce reading from disk costs.
62* `network` - [`Network`][`crate::entry::disks::Network`]
63    * Uses [`reqwest`](https://github.com/seanmonstar/reqwest) to read from a
64        remote resource.
65* `zstd` - [`ZstdDisk`][`crate::entry::disks::ZstdDisk`]
66    * [`zstd-rs`](https://github.com/gyscos/zstd-rs) compression and decompression.
67* `async_zstd` - [`ZstdDisk`][`crate::entry::disks::ZstdDisk`]
68    * `zstd`, but asynchronous.
69* `zstdmt`/`async_zstdmt` - [`ZstdDisk`][`crate::entry::disks::ZstdDisk`]
70    * Enable `zstd` with multithreaded compression support. May degrade performance;
71        test that the data compression speed actually benefits from this feature. This
72        is not necessary to compress multiple files with `zstd` at once, only to use
73        multiple threads for the compression of a single file.
74
75# Predefined Formats
76Formats can be custom-defined by implementing
77[`Encoder`][`crate::entry::formats::Encoder`] and
78[`Decoder`][`crate::entry::formats::Decoder`] (and/or the async versions).
79These features give ready to use defaults.
80
81(All formats use Serde, but the Serde traits do not implement over
82[`Read`][`std::io::Read`] and [`Write`][`std::io::Write`]).
83
84* `all_formats`
85    * Enable all formats.
86
87#### Synchronous Formats
88* `bincode` - [`BincodeCoder`][`crate::entry::formats::BincodeCoder`]
89    * Binary encoding format.
90* `serde_json` - [`SerdeJsonCoder`][`crate::entry::formats::SerdeJsonCoder`]
91    * Serde's flagship (de)serializer.
92* `simd_json` - [`SimdJsonCoder`][`crate::entry::formats::SimdJsonCoder`]
93    * Significantly faster than `serde_json`.
94* `csv` - [`CsvCoder`][`crate::entry::formats::CsvCoder`]
95    * Allows for reading from/writing to csv files.
96
97#### Async Formats
98* `async_bincode` - [`AsyncBincodeCoder`][`crate::entry::formats::AsyncBincodeCoder`]
99    * Binary format. NOT compatible with `bincode`, due to a size header.
100* `async_csv` - [`AsyncCsvCoder`][`crate::entry::formats::AsyncCsvCoder`]
101    * Compatible with `csv`.
102*/
