22# Motivating Example
23
24More examples that demonstrate more complex uses are in [`examples`].
25
26Assume that you have some `LargeStruct` that takes up significant storage and
27can be reduced to a smaller representation for searching. If it is stored in a
28collection where only a small number of elements are used, keeping them all
29loaded in memory wastes system resources. A
30[vector store](https://en.wikipedia.org/wiki/Vector_database) is one such
31structure. This example assumes a large, hashable type with only a few entries
32accessed.
33
34```rust
35# #[cfg(not(miri))] {
36#[cfg(all(feature = "bincode", feature = "array"))] {
37    use std::{
38        env::temp_dir,
39        iter::from_fn,
40    };
41
42    use serde::{Serialize, Deserialize};
43
44    use backed_data::{
45        entry::{
46            disks::Plainfile,
47            formats::BincodeCoder,
48        },
49        array::VecBackedArray,
50    };
51
52    # const BACKING_PATH: &str = "backed_data_motivating_example";
53    #[derive(Debug, PartialEq, Eq, Serialize, Deserialize)]
54    struct LargeStruct {
55        val: u8,
56    # /*
57        ...
58    # */
59    };
60
61    impl LargeStruct {
62        fn new_random() -> Self {
63            # /*
64              ...
65            # */
66            # Self { val: 1 }
67        }
68    }
69
70    const NUM_BACKINGS: usize = 1_000;
71    const ELEMENTS_PER_BACKING: usize = 1_000;
72
73    // This application only needs to find three random elements.
74    let query = [0, 10_000, 50_000];
75
76    // Do not use a temporary directory in real code.
77    // Use some location that actually guarantees memory leaves RAM.
78    let backing_dir = temp_dir().join(BACKING_PATH);
79    std::fs::create_dir_all(&backing_dir).unwrap();
80
81    // Define a backed array using Vec.
82    let mut backing = VecBackedArray
83        ::<LargeStruct, Plainfile, BincodeCoder<_>>::
84        new();
85
86    // Build the indices and backing store in 1,000 item chunks.
87    for _ in 0..NUM_BACKINGS {
88        let chunk_data: Vec<_> = from_fn(|| Some(LargeStruct::new_random()))
89            .take(ELEMENTS_PER_BACKING)
90            .collect();
91
92        // This is handled automatically by `DirectoryBackedArray` types.
93        let target_file = backing_dir.join(uuid::Uuid::new_v4().to_string()).into();
94
95        // Add a new bincode-encoded file that stores 1,000 elements.
96        // After this operation, the elements are on disk only (chunk_data
97        // is dropped by scope rules).
98        backing.append(chunk_data, target_file, BincodeCoder::default()).unwrap();
99    }
100    # assert!(backing.len() > 50_000);
101
102    // Query for three elements. At most 3,000 elements are loaded, because
103    // the data is split into 1,000 element chunks. Only 2,997 useless
104    // elements are kept in memory, instead of 99,997.
105    let results: Vec<_> = query
106        .iter()
107        .map(|q| backing.get(*q))
108        .collect();
109    # std::fs::remove_dir_all(backing_dir);
110}
111# }
112```

114# Usage
115
116The core structure is [`entry::BackedEntry`], which is wrapped by [`mod@array`]
117and [`directory`]. It should be pointed at external data to load when used.
118That data will remain in memory until unloaded (so subsequent reads avoid
119the cost of decoding). Try to only unload in one of the following scenarios:
120* The data will not be read again.
121* The program's heap footprint needs to shrink.
122* The external store was modified by another process.
123
124Each entry needs a [format][`entry::formats`] and (potentially layered)
125[disks][`entry::disks`] to use. The [`mod@array`] wrapper also needs choices of
126[containers][`array::Container`] to hold its array of keys and array of backed
127entries.
